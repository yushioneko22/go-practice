# 07 グラフ

このトピックでは、**面接で頻出する「グラフ」の表現方法と探索アルゴリズム**を学びます。

## なぜ必要か

SNSの友人関係、地図の経路探索、タスクの依存関係、ネットワークのルーティングなど、現実世界の問題の多くはグラフで表現できます。面接では「島の数（Number of Islands）」や「コースの履修可能性（Course Schedule）」が定番です。

## たとえ話

グラフは「駅と路線図」です。
- **ノード（頂点）** = 各駅
- **エッジ（辺）** = 駅をつなぐ線路
- **有向グラフ** = 一方通行の道路（AからBには行けるが、BからAには行けない）
- **無向グラフ** = 双方向の道路
- **隣接リスト** = 各駅から直通で行ける駅のリスト

---

## example/main.go の解説

### 1. 隣接リストによるグラフ表現 (10-25行目)

`map[int][]int` でグラフを表現します。各キーがノード、値がそのノードから到達できるノードのリスト。

### 2. BFS（幅優先探索） (27-50行目)

キューを使い、近いノードから順に探索します。最短経路の発見に使います。

### 3. DFS（深さ優先探索） (52-70行目) ★ここが一番重要

再帰またはスタックを使い、一本道を奥まで進んでから戻ります。全経路の列挙やサイクル検出に使います。

## 演習問題 I/O

### 演習1: 島の数（Number of Islands）
- 入力: 2Dグリッド（'1'=陸、'0'=水）
- 出力: `[Islands] 島の数: 3`

### 演習2: コース履修可能判定（Course Schedule）
- 入力: コース数と前提条件のペア
- 出力: `[Course] 全コース履修可能: true/false`

---

## 重要なTips

> [!TIP]
> 1. **visited配列は必須**: グラフにはサイクルがあり得るため、訪問済みチェックを忘れるとまず間違いなく無限ループします。
> 2. **BFS = 最短経路、DFS = 全探索**: 迷ったらBFSは「最短」を求める問題、DFSは「全パターン列挙」や「連結成分」を求める問題に使います。
> 3. **トポロジカルソート**: 「依存関係のある順序付け」にはトポロジカルソート（入次数管理 + BFS、またはDFS + 後処理）が定番です。
