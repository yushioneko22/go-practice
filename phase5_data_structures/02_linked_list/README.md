# 02 連結リスト

このトピックでは、**面接で頻出する「連結リスト」の操作と典型的な解法パターン**を学びます。

## なぜ必要か

連結リストはGoの標準ライブラリにはあまり登場しませんが、面接では非常に多く出題されます。ポインタ操作の理解、エッジケースの処理（空リスト、1要素）、そして再帰的思考を試すのに最適な題材だからです。

## たとえ話

連結リストは「宝探しゲームの地図」です。
- 各ノード = 宝箱（データを持っている）
- next ポインタ = 「次の宝箱の場所が書かれたメモ」
- 最後のノードの next = nil（「これが最後の宝箱だよ」というメモ）

配列と違い、宝箱は街中にバラバラに置かれています。メモを頼りに1つずつ辿るしかありません。

## example/main.go の解説

### 1. ノード定義と連結リストの構築 (8-20行目)

`ListNode` 構造体で値と次のノードへのポインタを持ちます。

### 2. リストの反転 (30-45行目) ★ここが一番重要

3つのポインタ（prev, current, next）を使って、リンクの向きを一つずつ逆転させます。面接の超頻出問題です。

### 3. リストの表示 (47-55行目)

デバッグ用にリストを `1 → 2 → 3 → nil` 形式で表示します。

## 演習問題 I/O

### 演習1: サイクル検出（Floyd's Algorithm）
- 入力: サイクルのあるリスト
- 出力: `[Cycle] サイクルが検出されました: true`

### 演習2: 2つのソート済みリストのマージ
- 入力: `1 → 3 → 5`, `2 → 4 → 6`
- 出力: `1 → 2 → 3 → 4 → 5 → 6 → nil`

---

## 重要なTips

> [!TIP]
> 1. **ダミーヘッドの活用**: マージやソートでは、先頭にダミーノードを置くとエッジケース処理が劇的に楽になります。
> 2. **Fast/Slowポインタ**: サイクル検出、中央値の発見など、2つのポインタを異なる速度で動かすテクニックは汎用性が高いです。
> 3. **紙に描く**: 連結リスト問題は必ずポインタの動きを紙に描きましょう。頭の中だけでは必ずバグります。
