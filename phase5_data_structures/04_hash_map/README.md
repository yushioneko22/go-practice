# 04 ハッシュマップ

このトピックでは、**面接で「計算量をO(n)に落とす切り札」であるハッシュマップの活用パターン**を学びます。

## なぜ必要か

ハッシュマップ（Goの `map`）は、検索・挿入・削除がすべて平均 O(1) という最強のデータ構造です。面接では「ブルートフォース O(n^2) をどう改善するか？」の答えがほぼ毎回ハッシュマップです。

## たとえ話

ハッシュマップは「図書館の索引カード」です。
- 本のタイトル（キー）を索引で引くと、棚番号（値）が即座にわかる
- 全棚を1つずつ探す（O(n)）必要がなく、索引を見れば O(1) で到着
- ただし、2冊の本が同じ棚番号に割り当てられる（衝突）こともある

## 演習問題 I/O

### 演習1: アナグラムのグループ化
- 入力: `["eat","tea","tan","ate","nat","bat"]`
- 出力: `[["eat","tea","ate"],["tan","nat"],["bat"]]`（順不同）

### 演習2: 最初の重複しない文字
- 入力: `"leetcode"` → 出力: インデックス `0`（'l'）
- 入力: `"loveleetcode"` → 出力: インデックス `2`（'v'）

## 重要なTips

> [!TIP]
> 1. **comma ok idiom**: `val, ok := m[key]` を使い、キーの存在を確認する習慣をつけましょう。ゼロ値と「存在しない」は別物です。
> 2. **mapの反復順序は不定**: Goのmapは意図的にランダムな順序で反復されます。順序が必要な場合はキーをソートしてください。
> 3. **カウント問題はmapで**: 「頻度」「出現回数」「重複」というワードが出たら、まずmapを思い浮かべましょう。
