# 01 配列・スライス操作

このトピックでは、**面接で最も頻出する「配列・スライス」を使った問題の解法パターン**を学びます。

## なぜ必要か

Google等の技術面接では、配列操作の問題が最初に出されることが多いです。配列はすべてのデータ構造の基礎であり、ここで詰まると先に進めません。実務でも、データのフィルタリング・変換・集計は日常的に行います。

## たとえ話

Goのスライスは「伸縮自在の本棚」です。
- `len` = 今並んでいる本の数
- `cap` = 本棚の最大収容数
- `ptr` = 本棚の設置場所（メモリアドレス）

本が増えて棚に入りきらなくなると、**より大きな本棚を新しく用意して引っ越す**（再アロケーション）のがGoの仕組みです。

## 演習問題 I/O

### 演習1: 配列の回転
- 入力: `[1,2,3,4,5,6,7]`, k=3
- 出力: `[5,6,7,1,2,3,4]`

### 演習2: 重複の除去（ソート済み配列）
- 入力: `[1,1,2,2,3,4,4,5]`
- 出力: `[1,2,3,4,5]`, 新しい長さ: 5

## 重要なTips

> [!TIP]
> 1. **計算量を常に意識**: 面接ではブルートフォース O(n^2) → 最適解 O(n) の改善を説明できることが重要です。
> 2. **スライスのコピーに注意**: `b := a` はシャローコピー。独立したコピーが欲しい場合は `copy()` を使いましょう。
> 3. **in-placeの意味**: 面接で「in-placeで解け」と言われたら、追加のスライスを作らずに元のスライスを直接操作する意味です。
