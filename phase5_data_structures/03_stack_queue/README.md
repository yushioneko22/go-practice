# 03 スタック・キュー

このトピックでは、**面接で頻出する「スタック」と「キュー」の実装と応用問題**を学びます。

## なぜ必要か

スタックとキューは、関数呼び出し（コールスタック）、タスクの処理順序（ジョブキュー）、構文解析など、あらゆるシステムの裏側で使われています。面接では「有効な括弧」問題が定番中の定番です。

## たとえ話

- **スタック** = レストランのお皿の山。最後に載せたお皿を最初に取る（LIFO: Last In, First Out）
- **キュー** = コンビニのレジ待ち行列。最初に並んだ人が最初にレジへ（FIFO: First In, First Out）

## example/main.go の解説

### 1. スライスによるスタック実装 (10-25行目)

Goには組み込みのスタック型がないため、スライスで実装します。`append` でpush、`s[:len(s)-1]` でpop。

### 2. スライスによるキュー実装 (27-42行目)

`append` でenqueue、`q[1:]` でdequeue。ただし先頭の削除は O(n) なので、大量データにはリングバッファを使います。

### 3. 有効な括弧の判定 (44-70行目) ★ここが一番重要

`()[]{}` の組み合わせが正しいかをスタックで判定する、面接の超頻出問題です。

## 重要なTips

> [!TIP]
> 1. **スタックを見たら再帰を疑え**: スタックで解ける問題は再帰でも解けます。面接では両方のアプローチを説明できると加点です。
> 2. **キューの先頭削除は遅い**: `q = q[1:]` は内部的にメモリリークの原因になりえます。本番では `container/list` やリングバッファを検討しましょう。
> 3. **Monotonic Stack**: 「次に大きい要素」系の問題では、単調減少スタックというテクニックが強力です。
