# 09 Defer and Panic

後片付けと例外的な強制終了の仕組みです。

## 1. 基本解説
### defer
`defer` の後に書かれた処理は、その関数の実行が終わる直前（`return` の後）に実行されます。
- ファイルを閉じる、ロックを外すといった「後始末」に非常に便利です。
- 同じ関数内に複数の `defer` がある場合、**逆順**（最後に宣言したものから先）に実行されます。

### panic / recover
- `panic`: 修復不可能なエラーが起きたときにプログラムを落とします。
- `recover`: 発生したパニックをキャッチして正常ルートに戻します（ただし、安易な利用は推奨されません）。

## 2. 重要なTips
> [!TIP]
> 1. **リソースリーク防止**: ファイルを開いたら、エラーチェックの直後に `defer f.Close()` を書く癖をつけましょう。これで閉じ忘れがなくなります。
> 2. **defer のタイミング**: `defer` は「関数」が終了するときに実行されます。大きな `for` ループの中で `defer` を使うと、ループが終わるまでリソースが解放されず溜まっていくので注意が必要です。
> 3. **panic よりも error**: 普通のプログラミング錯誤やバリデーションエラーには `error` を使い、`panic` は「データベースに接続できない」「メモリが足りない」といった致命的な場合に限定します。
