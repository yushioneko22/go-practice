# 02 二分探索

このトピックでは、**面接で必須の「二分探索」の基本と応用パターン**を学びます。

## なぜ必要か

O(n) の線形探索を O(log n) に改善する二分探索は、面接で最も問われるアルゴリズムの一つです。単純な配列検索だけでなく、「答えを二分探索する」という発想が様々な問題で使えます。

## たとえ話

二分探索は「辞書を引く時の戦略」です。
- "programming" を辞書で引くとき、先頭ページから1ページずつめくる人はいません
- まず真ん中を開いて「Mより前？後ろ？」→ 該当する半分だけに絞る
- これを繰り返すと、数回で目的のページに到着する

## example/main.go の解説

### 1. 基本的な二分探索 (10-30行目) ★ここが一番重要

ソート済み配列から目的の値のインデックスを見つける。`low`, `high`, `mid` の3ポインタの動かし方が基本。

### 2. lower_bound / upper_bound (32-55行目)

同じ値が複数ある場合に「最初の出現位置」「最後の出現位置」を見つける応用。

## 重要なTips

> [!TIP]
> 1. **off-by-oneに注意**: `low <= high` か `low < high` か、`mid+1` か `mid` か。境界条件を間違えると無限ループや見逃しが起きます。
> 2. **答えの二分探索**: 配列の中身ではなく「答えの範囲」を二分探索する問題もあります（例: 平方根、出荷日数の最小化）。
> 3. **sort.Search()**: Goの標準ライブラリに二分探索が用意されています。実務ではこちらを使いましょう。
