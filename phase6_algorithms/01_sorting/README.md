# 01 ソートアルゴリズム

このトピックでは、**面接で問われる代表的なソートアルゴリズムの仕組みと計算量の違い**を学びます。

## なぜ必要か

「このアルゴリズムの計算量は？」「なぜクイックソートが実用的に速い？」といった質問は面接の定番です。`sort.Sort()` を呼ぶだけでなく、内部の仕組みを理解していることが求められます。

## たとえ話

ソートは「トランプの手札を並べ替える方法の違い」です。
- **バブルソート**: 隣同士を比べて交換を繰り返す（初心者のやり方）
- **マージソート**: 手札を半分ずつに分けて、それぞれ並べてから合体（確実だが場所を使う）
- **クイックソート**: 基準のカードを決めて「それより小さい/大きい」に分ける（速いが運次第）

## example/main.go の解説

### 1. マージソート (12-45行目) ★ここが一番重要

分割統治法の代表。安定ソートで、最悪でも O(n log n)。ただし O(n) の追加メモリが必要。

### 2. クイックソート (47-75行目)

平均 O(n log n) だが最悪 O(n^2)。実用的には最速で、Goの `sort.Sort` も内部で使用。

## 重要なTips

> [!TIP]
> 1. **安定 vs 不安定**: 同じ値の要素の順序が保たれるかどうか。マージソートは安定、クイックソートは不安定です。面接で聞かれます。
> 2. **計算量の比較**: バブル O(n^2), マージ O(n log n), クイック 平均O(n log n)・最悪O(n^2)。空間計算量も述べられると加点。
> 3. **Goのsortパッケージ**: `sort.Slice()` が最も手軽。内部的にはイントロソート（クイック+ヒープ+挿入の組み合わせ）。
