# 05 動的計画法（DP）

このトピックでは、**面接最難関の一つ「動的計画法」の考え方と典型パターン**を学びます。

## なぜ必要か

DPはGoogle等の面接で最も差がつく分野です。再帰で指数時間かかる問題を多項式時間に落とせるため、「計算量を改善せよ」という問題の答えがDPになることが非常に多いです。

## たとえ話

DPは「過去の自分にメモを残す未来の自分」です。
- 同じ計算を何度もやるのは無駄（フィボナッチの素朴な再帰）
- 一度計算した結果をメモ（テーブル）に残しておけば、次に同じ問題に出くわしたとき即座に答えが分かる
- 「小さい問題の答え」を組み合わせて「大きい問題の答え」を構築する

## example/main.go の解説

### 1. 階段の登り方（Climbing Stairs） (10-30行目) ★ここが一番重要

1段か2段ずつ登れる階段。n段目への行き方は `dp[n] = dp[n-1] + dp[n-2]`。DPの最も基本的な例。

### 2. 状態遷移の可視化 (32-45行目)

各段の計算過程を表示し、DPテーブルの構築過程を見せます。

## 重要なTips

> [!TIP]
> 1. **DPの3ステップ**: (1) 状態を定義する (2) 遷移式を立てる (3) ベースケースを設定する。この順番で考えれば大抵の問題は解けます。
> 2. **トップダウン vs ボトムアップ**: メモ化再帰（トップダウン）から始めて、理解できたらDPテーブル（ボトムアップ）に変換すると書きやすいです。
> 3. **空間の最適化**: 2D DPでも「前の行しか参照しない」場合、1D配列に圧縮できます。面接で空間計算量を改善すると加点。
