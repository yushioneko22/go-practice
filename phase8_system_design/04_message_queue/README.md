# 04 メッセージキュー

このトピックでは、**非同期処理の要「メッセージキュー」の設計とGoのchannelによる実装**を学びます。

## なぜ必要か

マイクロサービス間の通信、バックグラウンドジョブ、イベント駆動アーキテクチャなど、メッセージキューは現代のシステムに不可欠です。面接では「Pub/Sub」「At-least-once delivery」などの概念を説明できることが求められます。

## たとえ話

メッセージキューは「郵便受け」です。
- **Publisher（送り手）**: 手紙を書いてポストに投函する
- **Queue（郵便局）**: 手紙を一時保管して、配達の順番を管理
- **Subscriber（受け手）**: 郵便受けから手紙を取り出して読む
- 送り手と受け手は直接会う必要がない（非同期・疎結合）

## 重要なTips

> [!TIP]
> 1. **バッファ付きchannel**: バッファなし = 同期、バッファ付き = 非同期。面接では「バッファサイズの選択基準」を聞かれることがあります。
> 2. **配信保証**: At-most-once（最大1回）、At-least-once（最低1回）、Exactly-once（正確に1回）の違いを説明できるように。
> 3. **永続化**: インメモリだけでは再起動時にデータが失われます。ファイル/DBへの永続化が実用上必要です。
