# 03 キャッシュシステム（LRU Cache）

このトピックでは、**面接で超頻出の「LRU Cache」を O(1) で実装する方法**を学びます。

## なぜ必要か

LRU（Least Recently Used）Cacheは、コーディング面接とシステムデザイン面接の両方で出題されます。ハッシュマップ+双方向連結リストの組み合わせで O(1) の Get/Put を実現する実装力が問われます。

## たとえ話

LRU Cacheは「冷蔵庫の食材管理」です。
- 冷蔵庫の容量は限られている（キャッシュサイズ）
- 新しい食材を入れる時、いっぱいなら「一番長く使っていない食材」を捨てる
- よく使う食材は手前に置く（最近使ったものを先頭に移動）

---

## example/main.go の解説

### 1. 双方向連結リスト + ハッシュマップ (10-40行目) ★ここが一番重要

Get/Put が O(1) で動くのは、ハッシュマップでノードに直接アクセスし、連結リストで順序を管理するため。

### 2. Get/Putの動作 (42-80行目)

Get: ノードを先頭に移動。Put: 新規追加 or 既存更新 + 容量超過時に末尾を削除。

---

## 重要なTips

> [!TIP]
> 1. **ダミーノード**: headとtailにダミーノードを使うと、エッジケース処理が激減します。
> 2. **LRU vs LFU**: LRU は「最も最近使われていない」、LFU（Least Frequently Used）は「最も使用頻度が低い」。面接で違いを聞かれます。
> 3. **実務での選択**: Goでは `sync.Map` やサードパーティの `groupcache` が使われますが、面接ではスクラッチ実装が求められます。
