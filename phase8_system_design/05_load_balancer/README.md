# 05 ロードバランサー

このトピックでは、**トラフィックを複数サーバーに分散する「ロードバランサー」の設計と実装**を学びます。

## なぜ必要か

1台のサーバーでは処理しきれないトラフィックを複数サーバーに分散するのがロードバランサーの役割です。面接では「どのアルゴリズムを使うか」「ヘルスチェックはどうするか」が問われます。

## たとえ話

ロードバランサーは「交通整理の警察官」です。
- 交差点（ロードバランサー）に来た車（リクエスト）を、空いている道路（サーバー）に振り分ける
- 工事中（ダウン中）の道路には車を送らない（ヘルスチェック）
- 道路の幅（サーバーの性能）に応じて、振り分ける量を変える（重み付き）

---

## アルゴリズム比較

| 方式 | 仕組み | 用途 |
|:---|:---|:---|
| Round Robin | 順番に1つずつ振り分け | 全サーバー同スペックの場合 |
| Weighted Round Robin | サーバーの重みに応じて振り分け | スペックが異なる場合 |
| Least Connections | 接続数が最も少ないサーバーに振り分け | 長時間接続がある場合 |
| IP Hash | クライアントIPのハッシュで振り分け | セッション維持が必要な場合 |

## 重要なTips

> [!TIP]
> 1. **ヘルスチェック**: 定期的にサーバーにpingして、応答がないサーバーをプールから除外する仕組みが必須。
> 2. **Sticky Session**: ログイン情報などを保持するため、同じユーザーを同じサーバーに送る必要がある場合があります。
> 3. **L4 vs L7**: L4（TCP層）のロードバランサーは高速、L7（HTTP層）はURLやヘッダーに基づく高度なルーティングが可能。
