# 04 決定版：カレンダーAPI比較プロジェクト

このプロジェクトでは、**「全く同じ仕様のカレンダーAPIを、標準ライブラリ・Gin・Echoの3パターンで実装」**し、それぞれの特徴を肌で感じます。

---

## 1. 共通仕様 (Design Doc)
作成するのは、予定を登録・取得するシンプルなAPIです。

- **データ構造 (Event)**:
  - `ID`: 整数
  - `Title`: 予定名
  - `Date`: 日付 (YYYY-MM-DD)
- **エンドポイント**:
  - `GET /events`: 登録済みの全予定をJSONで返す
  - `POST /events`: 新しい予定を1件登録する
- **保存方法**: 今回はメモリ上のスライスでOKです。

## 2. 実装のツボ (比較ポイント)
実装しながら、以下の違いに注目してください。

| 特徴 | 標準ライブラリ (`net/http`) | Gin | Echo |
| :--- | :--- | :--- | :--- |
| **ルーティング** | メソッド判定が手動 (`r.Method`) | `r.GET`, `r.POST` で直感的 | 同上 |
| **JSON解析** | `json.NewDecoder(r.Body)` が必要 | `c.ShouldBindJSON` で一撃 | `c.Bind` で一撃 |
| **JSON返却** | ヘッダーセットとエンコードが必要 | `c.JSON` で完結 | `c.JSON` で完結 |
| **可読性** | 処理が冗長になりがち | 非常にコンパクト | 非常にコンパクト |

## 3. 解説フロー (★重要)
各ディレクトリ（`full_scratch`, `gin`, `echo`）にある `main.go` を見比べてください。
- **10-15行目**: サーバーの土台作り
- **20-30行目**: データの「取得(List)」処理
- **35-50行目**: データの「作成(Add)」処理

この同じ行範囲に注目することで、コードの「密度の違い」がはっきり見えます。

---

## 4. 実行とテスト
それぞれのディレクトリに移動して起動してください。

```bash
# 例: Gin版を起動
cd gin
go run main.go

# テスト(POSTで追加)
curl -X POST -H "Content-Type: application/json" -d '{"title":"勉強会","date":"2026-03-25"}' http://localhost:8080/events
```

## 5. まとめ
「標準ライブラリの堅実さ」「Ginのスピード感」「Echoのバランス」……自分ならどれを選びたいか、ぜひ考えてみてください！
これが終われば、GoでWebアプリを作る準備は「満点」です。
