# 02 Standard Router (リクエストの解析とルーティング)

このコードは、**「URLに含まれるパラメータを読み取り、相手の要望に応じたデータを返す」**という、動的なWebアプリの基本機能を実現するためのサンプルです。

---

## 1. なぜ必要か
「こんにちは」と返すだけのサーバーは簡単ですが、実務では「IDが5番のユーザー情報を出す」「検索キーワードに一致する記事を出す」といった**動的な処理**が求められます。リクエストURLの一部やクエリパラメータを正確に切り出し、それに基づいて処理を分ける技術が必要です。

## 2. 比喩：ルーティングは「大型書店の案内板」
- **URLパス**: 「3階の技術書コーナー」のような場所の指定。
- **メソッド (GET/POST)**: 「本を借りる」のか「本を寄贈する」のか、というアクションの種類。
- **パラメータ**: 「その中のPythonというタイトルの本」という具体的な指名。

## 3. コード解説

### 01. クエリパラメータの取得 (12-14行目)
```go
query := r.URL.Query()
name := query.Get("name")
```
`r.URL.Query()` はURLの末尾に付く `?name=Gopher` といった情報を、辞書のように扱える形式で取り出します。

### 02. メソッドの判定 (18-22行目) ★ここが一番重要
```go
if r.Method != http.MethodGet {
    http.Error(w, "Method not allowed", http.StatusMethodNotAllowed)
    return
}
```
「データの取得（GET）」なのか「データの作成（POST）」なのかをチェックし、正しくない場合はエラーを返します。これがAPIの安全性を守る第一歩です。

---

## 4. 重要なTips
> [!TIP]
> 1. **標準ルーティングの限界**: 標準の `http.ServeMux` は、`/user/123` のような「パスの中間に可変のIDがある」形式の解析が苦手です。そのため、本番では後述のフレームワーク（Echo/Gin）を使うのが一般的です。 (※Go 1.22以降は改善されています)
> 2. **ステータスコードの明示**: 成功なら `200 OK`、間違いなら `400 Bad Request`。正しいステータスコードを返すことは、フロントエンド開発者への思いやりです。
> 3. **`favicon.ico` への注意**: ブラウザは勝手に `/favicon.ico` にリクエストを送ることがあります。ログに謎のアクセスがあっても驚かないでください。

## 5. まとめ
リクエストURLを解析できるようになると、サーバーは一気に「賢く」なります。相手が何を求めているかを正確に把握しましょう。

## 演習問題 I/O
### 仕様
- `/greet?name=XXX` にアクセスすると、`Hello, XXX!` と返してください。
- nameが空の場合は `Hello, Guest!` と返してください。
- メソッドが GET 以外の場合は、405 (Method Not Allowed) を返してください。

## 実行方法
```bash
cd exercise
go run main.go
# ブラウザで http://localhost:8080/greet?name=Taro にアクセス
```
