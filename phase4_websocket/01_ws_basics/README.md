# 01 WebSocket Basics (接続のアップグレードと基本通信)

このトピックでは、**「通常のHTTP通信をWebSocketにアップグレードし、双方向でデータをやり取りする」**ための最小限の仕組みを学びます。

---

## 1. なぜ必要か
通常のHTTP（REST APIなど）は、クライアントからの「お願い（Request）」に対してサーバーが「返事（Response）」をする一往復のみです。
しかし、チャットや通知、株価チャートなどの「リアルタイム性」が求められる機能では、サーバーから自発的にデータを送る必要があります。これを可能にするのが WebSocket です。

## 2. 比喩：WebSocket は「電話を繋ぎっぱなしにする」
- **HTTP**: 毎回ハガキを送って返事を待つ。
- **WebSocket**: 一度電話をかけ、受話器を置かずにずっと話し続ける状態。どちらからでも好きなタイミングで話しかけられる（双方向通信）。

## 3. コード解説

### 01. アップグレーダーの定義 (10-14行目) ★ここが一番重要
```go
var upgrader = websocket.Upgrader{
    CheckOrigin: func(r *http.Request) bool { return true },
}
```
HTTP通信を「WebSocket通信」という別次元のものに引き上げる（Upgrade）ための設定です。今回はテスト用に、どこからの接続も許可するようにしています。

### 02. 書き込みと読み込み (20-30行目)
```go
err := conn.WriteMessage(websocket.TextMessage, []byte("Hello!"))
messageType, p, err := conn.ReadMessage()
```
`WriteMessage` で送信、`ReadMessage` で受信します。これは一度きりではなく、ループさせることで何度でもやり取りが可能です。

---

## 4. 重要なTips
> [!TIP]
> 1. **接続の終了**: `defer conn.Close()` を必ず呼び出し、通信が終わったら回線を切断するようにします。
> 2. **無限ループ**: 受信処理などは通常 `for` ループの中で行います。
> 3. **エラーハンドリング**: 相手がブラウザを閉じたり回線が切れたりすると、`ReadMessage` などでエラーが返ります。これを検知して適切に後片付けを行うのが実務の要です。

## 5. まとめ
WebSocket の第一歩は「HTTPからのアップグレード」です。一度繋がってしまえば、あとは自由にデータを流すことができます。
